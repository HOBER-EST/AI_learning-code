# 61A 递归实验室 · 使用说明

这是一个面向 CS61A 学习者的 Python 学习平台：上传或编写代码、自动运行测试、逐步可视化递归调用过程和环境图（Environment Diagram），并围绕 **递归（Recursion）**、**链表（Link）** 和 **树（Tree）** 提供交互式练习与 AI 导师。

---

## 1. 启动平台

### 方式一：桌面版（推荐，无需安装 Python / Node）

1. 在 GitHub 仓库的 **Releases** 页面（或 Actions 中 “Desktop app” 工作流的 Artifacts）下载对应系统的安装包：

   | 系统 | 文件 |
   | --- | --- |
   | Windows | `Learn61A-windows-x86_64.zip` |
   | macOS | `Learn61A-macos-arm64.zip`（Apple 芯片） |
   | Linux | `Learn61A-linux-x86_64.tar.gz` |

2. 解压后启动：
   - **Windows**：打开 `Learn61A` 文件夹，双击 `Learn61A.exe`。如果出现 “Windows 已保护你的电脑”，点 **更多信息 → 仍要运行**。
   - **macOS**：把 `Learn61A.app` 拖进“应用程序”。第一次打开时请**右键点击 → 打开**，在弹窗中再点“打开”（或在“系统设置 → 隐私与安全性”中点“仍要打开”）。
   - **Linux**：运行 `Learn61A/Learn61A`。

3. 程序会打开一个独立窗口，所有功能与网页版相同。关闭窗口即退出。

说明：

- 安装包没有经过 Apple / 微软的付费代码签名，所以第一次打开时系统会提示“无法验证开发者”，按上面的步骤放行即可。
- 如果系统缺少内嵌网页组件（常见于部分 Linux 发行版），程序会自动改用默认浏览器打开，此时关闭终端窗口即退出。想总是用浏览器，可以加参数 `--browser` 启动。
- 设置了 `ANTHROPIC_API_KEY` 环境变量后再启动，同样可以使用 Claude 导师。
- 桌面版在本机运行，代码不会上传到任何服务器（使用 Claude 导师时除外）。

### 方式二：从源码运行（开发者）

需要 Python 3.10+ 和 Node.js 20.19+（推荐 22）。在项目根目录执行：

```bash
make install   # 安装后端（backend/.venv）和前端依赖
make dev       # 同时启动后端 :8000 和前端 :5173
```

然后在浏览器打开 <http://localhost:5173>。

不使用 make 时，可以分别启动：

```bash
# 终端 1：后端
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
.venv/bin/uvicorn app.main:app --port 8000 --reload

# 终端 2：前端
cd frontend
npm install
npm run dev
```

**单进程部署：** `make serve` 会先构建前端，再由后端在 <http://localhost:8000> 同时提供页面和 API。

**自己打包桌面版：** 在哪个系统上打包就得到哪个系统的版本（PyInstaller 不能跨平台编译）：

```bash
make desktop   # 产物在 desktop/dist/，压缩包在 desktop/release/
```

## 3. 代码实验室

### 3.1 编写或上传代码

- 直接在编辑器里写代码；内容会自动保存在浏览器中。
- 点击 **📂 上传 .py**，或把 `.py` 文件**直接拖到编辑器上**。上传后平台会：
  1. 检查语法（有语法错误会提示行号）；
  2. 列出文件中的函数；
  3. **自动运行测试**，结果显示在右侧“测试结果”标签页。
- **📚 载入示例** 提供阶乘、斐波那契、汉诺塔、闭包、Link、Tree、tree ADT、列表别名等示例，以及一个故意写错的递归（适合试用 AI 导师）。

单个文件上限 100 KB，必须是 UTF-8 编码。

### 3.2 运行与测试

- **▶ 运行**：执行整个程序，显示输出和错误回溯（traceback）。
- **✓ 运行测试**：自动收集并执行
  - 函数文档字符串中的 **doctest**：

    ```python
    def square(x):
        """
        >>> square(3)
        9
        """
        return x * x
    ```

  - 名字以 `test` 开头、没有参数的函数（用 `assert` 断言）：

    ```python
    def test_square():
        assert square(4) == 16
    ```

测试结果中，未通过的用例排在最前面，并列出“期望”与“实际”输出。每个用例有独立的时间限制（默认 2 秒），所以一个死循环只会让那一个用例超时。

> 小技巧：未通过的用例旁边有 **🔍 可视化** 按钮，点击后会把这个调用追加到代码末尾，直接进入可视化，看看哪一步出了问题。

### 3.3 可视化执行

在 **可视化调用** 输入框中填写要观察的调用（例如 `fact(4)`），点击 **🔍 可视化执行**。

- 如果代码末尾已经有调用语句，输入框可以留空。
- 如果代码只有函数定义且留空，平台会自动使用第一个 doctest 中的调用（输入框中会提示“（自动）”）。

进入可视化后：

- **步进控制**：⏮ 第一步、◀ 上一步、下一步 ▶、⏭ 最后一步、⏵ 自动播放（可选慢 / 中 / 快），也可以拖动进度条，或用键盘 **← →**。
- **代码区**：绿色箭头 ➜ 是刚执行的行，红色箭头 ➜ 是下一步要执行的行。
- **步骤说明**：显示“调用 fib(3)，创建新帧 f3”“fib(1) 返回 1”等描述。
- **程序输出**：显示到当前步骤为止的 `print` 输出。

最多记录 1000 步。如果达到上限，平台会提示可能存在**无限递归**。

### 3.4 如何读环境图（Environment Diagram）

环境图按 CS61A 的约定绘制：

- **Global frame**：全局帧，列出全局名字。
- **f1: fact [parent=Global]**：每次函数调用创建一个新帧，按创建顺序编号；`parent` 是**定义该函数时所在的帧**（不是调用它的帧）。lambda 函数的帧显示为 `λ <line 行号>`。
- **Return value**：函数返回后，帧中会显示返回值。
- 帧的颜色：红色左边框 = 当前帧；蓝色左边框 = 仍在调用栈上；灰色 = 已经返回。勾掉“显示已返回的帧”可以只看调用栈上的帧，适合很深的递归。
- 右侧是**对象**：数字、字符串等简单值直接写在帧里；列表、字典、函数、`Link`、`Tree` 等对象画在右侧，用**箭头**指向。从当前帧出发的箭头以红色高亮。
- 函数对象显示为 `func fact(n) [parent=Global]`。
- `Link` 画成盒子-指针（box-and-pointer）链：每个节点有 `first` 和 `rest` 两格，`rest` 指向下一个节点，`∅` / `()` 表示 `Link.empty`。
- `Tree` 画成一棵树：每个圆角节点是一个 `label`，下方连线连接它的 `branches`。
- 内部函数的自由变量（例如闭包里的 `n`）不会出现在内部函数的帧中——按照 CS61A 的规则，它们在 parent 帧中查找。

### 3.5 如何读递归调用树

“递归调用树”标签页把每一次函数调用画成一个节点，父节点是发起调用的那一次调用：

- 节点颜色：**红框黄底** = 当前正在执行；**蓝色** = 在调用栈上等待子调用返回；**绿色** = 已返回（下方显示 `→ 返回值`）；**红色** = 因异常退出。
- 顶部统计：已发生的调用次数、当前栈深度、最大深度。
- **重复子问题**：同样的调用（如 `fib(1)`）出现多次时，节点右上角会标出 `×次数`，顶部列出重复最多的调用——这正是记忆化（memoization）的动机。
- 勾选“显示尚未发生的调用”可以预览整棵调用树（虚线）。
- **点击任意节点**会跳转到这次调用发生的那一步。
- `−` / `+` 按钮缩放；树很大时，视图会自动滚动到当前调用。

### 3.6 内置的 CS61A 工具

无需导入即可直接使用（也可以在代码中定义自己的版本覆盖它们）：

| 名字 | 说明 |
| --- | --- |
| `Link(first, rest=Link.empty)` | 链表；`lnk.first`、`lnk.rest`、`Link.empty`；`print(lnk)` 显示为 `<1 2 3>` |
| `Tree(label, branches=[])` | 树；`t.label`、`t.branches`、`t.is_leaf()`；`print(t)` 按缩进显示 |
| `tree(label, branches=[])` | 函数式 tree ADT 构造函数 |
| `label(t)`、`branches(t)`、`is_leaf(t)`、`is_tree(t)` | 函数式 tree ADT 选择器 |
| `print_tree(t)` | 打印函数式 tree |

## 4. 交互式练习

1. 在 **练习** 页面选择题目。题目按主题分组，★ 表示难度，✓ 表示已完成。
2. 阅读题目说明和 **代码要求**（例如“必须使用递归”“不能使用循环”）。
3. 在编辑器中实现函数，代码会自动保存（刷新页面不会丢失）。
4. **✓ 运行示例测试**：只运行代码中的 doctest，快速自检。
5. **🚀 提交**：运行全部官方测试（包含**隐藏测试**）并检查代码要求，全部通过即完成练习。
6. 卡住了？
   - **💡 提示**：逐条展开，从思路到具体步骤；
   - **🔍 可视化**：输入框里已经预填了一个合适的调用；
   - **AI 导师** 标签页：分析代码并回答问题；
   - **🔑 查看参考答案**：建议最后再看。
7. **↺ 重置** 恢复初始代码。

学习进度保存在当前浏览器中。

## 5. WWPD 测验

每道题给出一段代码和一个表达式，请填写交互式 Python 解释器会显示的内容：

- 按解释器的显示填写，字符串要带引号，例如 `'done'`；
- 如果会报错，填写 `Error`；
- 如果结果是函数，填写 `Function`；
- 多行输出逐行填写；返回 `None` 时解释器什么也不显示（`print(None)` 才会显示 `None`）。

点击 **检查答案**（或按 Ctrl/⌘ + Enter）查看对错和解析；**在实验室中可视化** 会把这道题的代码带到实验室，方便画出环境图。

## 6. AI 导师

AI 导师在“测试结果”旁边的 **AI 导师** 标签页中：

- **代码诊断**：基于静态分析（AST）识别常见问题，例如
  - 递归缺少基本情况（base case）、递归参数没有变小；
  - 递归调用的结果被丢弃、某些路径没有 `return`；
  - 把 `.rest` 与 `None` 比较（应使用 `Link.empty`）、`t.branches()` 多加了括号、`if t.is_leaf:` 忘记调用；
  - 结合测试结果解释 `RecursionError`、超时、对 `None` 运算、访问空链表属性等运行时错误。

  还会标出每个递归函数是“线性递归”还是“树递归”，以及是否检测到基本情况。
- **提问**：输入问题，或点击 **帮我看看哪里错了**。

导师有两种模式（右上角会显示当前模式）：

| 模式 | 条件 | 说明 |
| --- | --- | --- |
| 离线规则 | 默认 | 根据静态分析和测试结果给出提示，完全离线可用 |
| Claude | 后端设置了 `ANTHROPIC_API_KEY` | 由 Claude 以 CS61A 助教的身份进行苏格拉底式引导，不会直接给出完整答案 |

启用 Claude 导师：

```bash
export ANTHROPIC_API_KEY=sk-ant-...
make dev
```

如果 Claude 暂时不可用，平台会自动退回离线规则模式。

## 7. 运行限制与安全

学生代码在独立的、受限的 Python 子进程中运行：

- 每次运行有时间限制（运行 5 秒、测试 20 秒、单个测试用例 2 秒、可视化 10 秒）和内存限制（512 MB；Windows 和 macOS 上不限制内存，只限制时间）；
- 禁止写文件、创建子进程、访问网络；`input()` 不可用（请把数据直接写在代码里）；
- 可视化最多记录 1000 步，堆中最多显示 300 个对象。

> 这些措施适合课堂和个人学习使用，并不是严格的安全沙箱。若要公开部署，请再把后端放进容器等隔离环境中。

## 9. 常见问题

**可视化只显示了函数定义，没有调用？**
在代码末尾加一行调用，或在“可视化调用”输入框中填写，例如 `fact(4)`。

**提示“已达到最大步数”？**
多半是无限递归：检查基本情况能否被达到，以及每次递归的参数是否在向基本情况靠近。也可能只是输入太大——换一个更小的输入来可视化。

**doctest 明明输出一样却没通过？**
检查空格、引号和换行。返回 `None` 的表达式在 doctest 中不应写任何期望输出。

**为什么内部函数的帧里没有外层变量？**
这是 CS61A 环境图的规则：自由变量在 parent 帧中查找，所以只画在定义它的帧里。

**页面提示“无法连接后端服务”？**
确认后端已经在 8000 端口启动（`make dev` 会同时启动前后端）。
